Questions and concise answers

Why choose Blazor?
It uses C Sharp for both interface behaviour and application logic, supports reusable components and provides server interaction through the framework's SignalR circuit.

What is functional programming in this project?
QueueRules contains deterministic functions with no database or mutable shared state. Given the same inputs, they return the same result. Records carry operation results and view data.

Why use a DbContext factory?
A Blazor circuit can live much longer than one request. A new context per operation avoids sharing a long-lived context across overlapping UI events.

Why use a lock and a unique index?
The lock serializes writes within this process. The unique index enforces the invariant in the database. They address different layers of consistency.

What happens if two users book the same slot?
One transaction wins. The other sees that the slot is already reserved or encounters the database constraint and receives an error result.

How is waiting time calculated?
Waiting visitors ahead multiplied by configured minutes per visit, plus one visit if a counter is busy. It is an estimate and does not predict the exact finishing time.

Does an appointment skip the queue?
No. It reserves an arrival window. Check-in creates a live ticket in normal arrival order. The interface states this explicitly.

Where is SignalR used?
Interactive Server uses SignalR for its browser circuit. QueueChanges tells components that committed data changed, and the framework sends the rendered updates. There is no separate custom hub.

What happens on disconnection?
The saved ticket stays in SQLite. The browser attempts to reconnect. After reloading, the page reads the current state. Failed notification subscribers cannot roll back successful writes.

How is operator access protected?
The route requires the Operator role, and every staff service method independently checks the current database role. Hiding a button alone is not authorization.

What would change for a large deployment?
Use a server database, distributed notifications, reliable numbering, migrations, controlled account administration, monitoring and load testing. The current version is single-instance.

What did testing verify?
The recorded local run passed 62 unit, SQLite integration and HTTP flow cases. Coverage is reported for instrumented C Sharp code. Browser tests and a manual checklist are included, and their execution status must be stated accurately.
